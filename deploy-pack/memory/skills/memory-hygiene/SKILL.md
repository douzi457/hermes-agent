# Memory Hygiene Skill

本技能管记忆的写入与整理纪律（方案 M2/M3）：让 MEMORY.md / USER.md 长期只保留一个现行版本、不自相矛盾、不撞上限。它不改变框架的存储机制——框架原生只有精确去重与超限拒绝，语义层面的合并、替代、降级全靠本规程执行。它也不管 journal 里的流水写法，只管长期层。

## When to Use

- 任何准备往 MEMORY.md / USER.md 写入之前（先想该不该写、写哪层）。
- 值班 Job 04（每晚整理）与 Job 05（每周体检）执行时。
- 写入被拒（超限）、发现两条记忆互相矛盾、用户纠正了一条旧记忆时。

## Prerequisites

- 分层约定见装配包 memory/README.md（M1）：长期层、journal 轨迹层、people 关系层、archive 归档层的位置与预算（长期层目标 ≤ 上限 80%）。
- 体检工具：`python3 "$HERMES_HOME/scripts/memory_health.py" "$HERMES_HOME/memories"`（部署位置见 memory/README.md 的部署顺序）。
- 整理规程全文在装配包 memory/consolidate-protocol.md；执行整理时先 `read_file` 读它。

## How to Run

日常写入走 Procedure A；整理走 Procedure B。两个流程共用一把尺子：**写之前先读现文件**。读现文件用 `read_file`，改条目用 `memory` 工具或 `patch`，禁止整文件重写 MEMORY.md（会绕过框架的条目切分与上限检查）。

## Quick Reference

- 五条写入纪律：当场记、只记耐久、写前读旧条、新替旧、条带日期与来源
- 改旧条优先于加新条：能 patch/replace 就不要 add
- 长期层目标占用 ≤80%；≥95% 时先腾位再写新条
- 判定不了的矛盾进「待用户裁决」，不许擅自删

## Procedure

### A. 写入（每一轮都适用）

1. 先分层：这是长期结论（MEMORY）、用户画像（USER）、当日细节（journal）、人物事实（people）哪一类？分错层就先写对层，长期层不收细节。
2. 用 `read_file` 读目标文件，找有没有同一事项的旧条目。
3. 有旧条且结论变了：走「新替旧」——改旧条本身，被替代的细节追加进当日 journal，注明替代日期。
4. 有旧条且只是补充：在旧条上 patch 增补，不新开一条。
5. 确无旧条才 add 新条，条目结尾统一带「（YYYY-MM-DD，来源）」，来源只用三类：用户自述 / 已核实 / 观察（推断必须标观察，不许写成已核实）。
6. 写入后确认回执：成功才说「记住了」；被拒（超限或待批）时明说原因与下一步（如先跑一轮整理腾位），不许假装记下。

### B. 整理（Job 04/05 或人工触发）

1. 跑体检脚本拿确定性数据，再通读 MEMORY.md / USER.md 全文。
2. 按《整理规程》的四种处置逐项处理：合并、新替旧、降级、归档；每项判定标准以规程为准。
3. 疑似矛盾判定不了的，进变更摘要「待用户裁决」区，原文、日期、你的倾向都写全。
4. 产出变更摘要（格式见规程），数字只用脚本与 git 记录里的，不许估算。
5. 整理前后各做一次 git 提交（memories 目录），失败即停手并上报。

### 正反例

- ✗ 反例：用户说「预算从 3000 改成 5000」→ 新增一条「预算 5000」与旧条并存。两条都会被全文注入，下次必然自相矛盾。
- ✓ 正例：同一句话 → 先读到旧条「预算 3000（2026-09-01，用户自述）」，patch 改为「预算 5000（2026-10-23，用户自述；原 3000 已替代）」，旧值沉 journal。
- ✗ 反例：把某次任务的完整参数表贴进 MEMORY.md。参数是一次性的，占长期层额度还会过期。
- ✓ 正例：长期层只留「该任务的默认参数已定版，详见 journal 2026-10-23」，细节进 journal。
- ✗ 反例：把推测写成事实——「用户应该更喜欢深色封面（已核实）」。
- ✓ 正例：「观察到用户两次选了深色封面（2026-10-20、2026-10-22，观察）」——观察就标观察。

## Pitfalls

- 用整文件重写代替条目级修改：绕过框架上限检查，还可能冲掉并发写入与用户手改。
- 把 write_approval 的待批当故障：部署初期它就是开着的，后台写入进待批区是正常流程，提醒用户用 `/memory pending` 抽查即可，不要建议关掉来「解决问题」。
- 整理时为了数字好看过度合并：合并错一条的代价远大于多留一条，拿不准就进待裁决。
- 忘了快照是会话开始的冻结版：本会话内刚写的记忆，本会话的系统提示不会变；引用「我现在的记忆」时以盘上文件为准，不要凭提示快照断言。

## Verification

- 抽三条最近写入的条目：都有日期与来源标注，且在现文件里找不到同一事项的第二个版本。
- 跑一次体检脚本：占用 ≤80% 或有明确的腾位计划；完全相同条目组为 0。
- 故意让用户纠正一条旧记忆：下一轮检查旧条已被新替旧、journal 有留痕、变更摘要或当场回复里有交代。
